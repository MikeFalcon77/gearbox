# Демо 2026-09-30: от готовых gear'ов до своего репозитория

Сценарий прогнан целиком 2026-09-29 на release-движке. Две ошибки, найденные на прогоне, исправлены в `4333295`:
- Create Gear на продукте из blank-шаблона падал с GBX0101;
- после Create Gear висел устаревший GBX0301.

Тайминги ниже взяты с того прогона.

## Подготовка (за час до демо)

1. Ветка `gears-rust` — `feature/gearbox`: `git -C ../gears-rust branch --show-current`.
2. Собрать движок и Studio:
   ```sh
   cargo build --release -p gearbox-cli
   cd ide && nvm use && env -u SSL_CERT_FILE npm run build
   ```
3. Запустить Studio на release-движке. Debug-движок открывает продукт примерно в 3 раза медленнее.
   ```sh
   cd ide && env -u SSL_CERT_FILE GEARBOX_ENGINE=$PWD/../target/release/gearbox npm run start:browser
   ```
   Открыть http://127.0.0.1:3000/, окно 1600×1000, светлая тема.
4. Прогреть общий target (на прогоне холодная сборка заняла 1 мин 26 с, 460 крейтов). Достаточно один раз собрать любое дерево с тем же набором gear'ов, например `CARGO_TARGET_DIR=../gears-rust/target cargo build` в `.gearbox/payments-demo/dev`.
5. Убрать следы прошлых прогонов:
   ```sh
   rm -rf products/demo-shop ~/projects/demo-shop-app ~/projects/demo-shop-app-prod
   git status --short products   # пусто
   ```
6. Держать открытыми: терминал в `~/projects` и этот файл. Заготовки лежат в `docs/demo/assets/`.

## Сценарий

### 1. Продукт из готовых gear'ов (~3 мин)
- Start → **New Product** → Blank, id `demo-shop`, name `Demo Shop`. Destination: взять подсказку из поля, это `products/demo-shop/product.gdl`. Create → Accept.
  - В списке Sources checkout gearbox серый с пометкой «contains the destination». Это нормально, скажи одной фразой.
- **Add Gear** по очереди. В каждой панели показываем «What changes» и строку, которая будет записана.
  1. `api-gateway`. Подтянет authn-resolver, grpc-hub, types-registry и приложение demo-shop. Появится предупреждение GBX0315 (у grpc-hub нет gRPC-регистранта). Это хороший момент показать, что проверки видны до записи.
  2. `gear-orchestrator`: снимает GBX0315.
  3. `authn-resolver` → плагин `static-authn-plugin` → Attach, «All profiles».
  4. `nodes-registry`.
- Вкладка **Validation** для `dev`: 0 ошибок, 0 предупреждений.

### 2. Свой gear (~3 мин)
- Кнопка **Create Gear** внутри продукта. Kind **Service**, id `greeter`, Name `Greeter` (по умолчанию стоит «New Gear»). Папку оставить: `products/demo-shop/gears`.
- Справа показать предпросмотр трёх файлов: `gear.gdl`, `Cargo.toml`, `src/lib.rs` со скелетом `#[toolkit::gear]`.
- Create → в диалоге 2 правки: `source(id = "gears", …)` и `use_gear("greeter", …)` → Accept.
- Studio переоткроет продукт, это займёт несколько секунд. Validation чистая, greeter есть в Composition.

### 3. Дописываем код (~2 мин)
- В `products/demo-shop/gears/greeter/`:
  - `src/lib.rs` ← `docs/demo/assets/greeter-lib.rs`. Это один REST-эндпоинт, в атрибуте добавлено `capabilities = [rest]`.
  - В `Cargo.toml` под `[dependencies]` добавить:
    ```toml
    axum = "0.8"
    serde = { version = "1", features = ["derive"] }
    ```
- Toolbar **Resolve** → Validation 0/0.

### 4. Генерация в свой репозиторий (~2 мин)
- Toolbar **Generate**. Output folder: `~/projects/demo-shop-app` (вписать полный путь и нажать Enter, или Choose…). Галка «Make it a git repository» стоит по умолчанию → **Apply**.
- На прогоне: 8 файлов create, после Apply 8 written и бейдж «git repository created, first commit …».
- Почему `~/projects`, а не `/tmp`: пути к gear'ам в Cargo.toml получаются короткими (`../gears-rust/...`), а Docker-контекст — `~/projects`.

### 5. Сборка и запуск (~1 мин при тёплом target)
```sh
cd ~/projects/demo-shop-app
git log --oneline                     # Generated by Gearbox Studio
CARGO_TARGET_DIR=../gears-rust/target cargo build
../gears-rust/target/debug/gbx-demo-shop --config config/demo-shop.yaml run
# во втором терминале:
curl -s http://127.0.0.1:8087/healthz            # ok
curl -s http://127.0.0.1:8087/greeter/v1/hello   # {"message":"Hello from a gear written five minutes ago"}
```
- Префикса `/cf` нет: в конфиге не задан `prefix_path`. Запрос на `/cf/...` вернёт 401.
- Остановить: Ctrl+C или `pkill -f gbx-demo-shop`.

### 6. Kubernetes: шаблоны → артефакты деплоя (~4 мин)
- Overview → **Add profile…** → id `prod`, kind kubernetes, discovery static → Add.
- Затем в полях профиля задать namespace `demo` и image_registry `registry.example.com/demo` → Apply changes.
- **Вынести greeter в отдельное приложение.** В UI этого нет: Topology только для чтения. Скажи прямо и допиши в `product.gdl` после `gears = [...]`:
  ```
  applications = [
      application("greeter", anchor = "greeter", profiles = ["prod"]),
  ],
  ```
  Переключить профиль на `prod` → Topology покажет 2 приложения: api-gateway (host) и greeter (worker). Validation — 1 предупреждение GBX0603, как у payments-demo.
- Generate для `prod` → Output folder `~/projects/demo-shop-app-prod` → Apply. На прогоне было 35 файлов. Показать дерево:
  - `docker/{api-gateway,greeter}/Dockerfile`, `docker/build.sh`;
  - `helm/demo-shop/` — umbrella-чарт, `values.schema.json` и сабчарты `charts/{api-gateway,greeter}/templates/{deployment,service,configmap,serviceaccount}.yaml`.
- **Свой шаблон.** Скопировать `docs/demo/assets/Dockerfile.jinja` в `products/demo-shop/templates/docker/Dockerfile.jinja`. Это встроенный шаблон плюс строка `LABEL org.opencontainers.image.vendor="Acme"`.
  - Generate перепланирует: «2 update … 1 overridden». Клик по Dockerfile показывает diff с LABEL.
  - Apply → `git -C ~/projects/demo-shop-app-prod diff` покажет LABEL в обоих Dockerfile'ах.
- Рендер чарта: `helm template ~/projects/demo-shop-app-prod/helm/demo-shop | head -40`. На прогоне helm v3.11: exit 0, `helm lint` без ошибок.

### 7. Существующая инфраструктура — только рассказать
Слайд 18 деки, текст в заметках к нему.
- Сегодня продукт генерирует всю свою топологию.
- Дальше: `installation(...)` описывает то, что уже развёрнуто (platform host, directory service, общие gear'ы). Новый продукт ссылается на инсталляцию, генерируется только новое, и gear ходит к платформе по контракту.
- Спроектировано в ADR-0016 и ADR-0018 (proposed), не построено.

## Чего не делать и что сказать, если спросят
- **Не запускать `docker/build.sh`.** Он строит из общего предка всех корней. Образы не собирались и в кластер не выкатывались. Честная формулировка: «helm template и lint проходят, в кластер не деплоили».
- **Выходной репозиторий не самодостаточен.** Gear'ы подключены path-зависимостями: к `gears-rust` и к `products/demo-shop/gears/greeter`. Реестр и git-источники — следующий шаг.
- **Namespace профиля не попадает в чарт.** Он задаётся при установке (`helm install -n demo`).
- **Счётчик «8 create» после Apply не меняется.** Смотреть на бейдж «8 written».
- **New Product пишет только внутри репозитория.** Это известное ограничение (`docs/plans/prototype.md` §13 п. 13), а Generate уже умеет писать в любую новую папку.
- **После демо demo-shop останется в Recent.** Если удалить `products/demo-shop`, открыть его оттуда не получится.

## Запасные пути
- Studio не отвечает → перезапустить (п. 3 подготовки). Продукт на диске, открыть через Recent.
- Create Gear отказал → создать gear в той же папке и дописать в `product.gdl` руками: `source(id = "gears", at = path("gears"))` и `use_gear("greeter", source = "gears")`.
- Generate в папку отказал («already holds … and no product.lock») → выбрать новую пустую папку.
- Долгая сборка → показать готовое дерево и запуск из прогона: `/tmp/gearbox-review/demo-shop-app` (собрано, запускалось), скриншоты `/tmp/gearbox-review/demo-shots/`.
- Всё через CLI:
  ```sh
  cargo run -q -p gearbox-cli -- generate --root ../gears-rust --root products/demo-shop/gears \
    --product products/demo-shop/product.gdl --profile dev --out ~/projects/demo-shop-app/app
  ```
  У CLI `--out` кладёт кэш слияния в родителя (`.base`), поэтому нужна подпапка.
